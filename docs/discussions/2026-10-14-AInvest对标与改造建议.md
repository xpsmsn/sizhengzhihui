> 日期：2026-10-14
> 对标样本：`https://139.196.156.236/ainvest/`（同样是基于 AIHOT 搭建的站点，AI 产业链投研终端）
> 本文记录：对标发现 → 可借鉴清单 → 痛点诊断 → P0 改造方案与落地明细 → 部署验证 → 后续路线。

## 一、结论摘要

用户提出的痛点只有一个：**详情页单调**——AI 导读字数太少、没有图片、信息量不足以支撑阅读，只能把用户导去原文。

对标的启发是：AInvest 的"信息密度"不是靠文章配图堆出来的，而是靠 **结构化专题 + 数据可视化 + 分节叙事**（"来龙去脉"）。所以对策不是"多放一张图"，而是：

1. **把一句导读扩成一段结构化解读**（速览 / 要点 / 背景 / 意义与影响 / 原文金句 / 对读者的启示 / 思考题）；
2. **详情页按固定骨架重排**，让每一屏都有可读内容；
3. **复用站内已有的图片代理，从原文抽取配图**作为头图。

以上三点即本轮 P0，代码已完成、类型检查通过，待部署。

## 二、AInvest 是什么

一个纯前端 SPA（`app.js` 约 80KB），后端是若干 JSON 接口。模块以"投研终端"的方式组织，**每个模块背后都是结构化数据，而不是文章流**：

| 模块 | 作用 | 接口 |
| --- | --- | --- |
| 全球指数 / 行情快照 | 顶部状态条 | `/api/bootstrap` |
| 今日焦点 | 头条聚合 | `/api/feed` |
| 专题聚合 | 一个事件一个专题页，"来龙去脉"分节叙事 | `/api/topics`、`/api/topic/{id}` |
| 热力图 / 轮动 | 板块资金流向可视化 | `/api/heatmap`、`/api/rotation` |
| 技术成熟度曲线 | 产业阶段定位 | `/api/physmap`、`/api/mapping` |
| 产业图谱 | 节点-关系图 | `/api/mapping`、`/api/node/{id}` |
| 图解产业链 | SVG 静态图解 | 前端内置 |
| 宏观研究 / 泡沫监控 | 主题看板 | `/api/macro`、`/api/bubble` |
| 业绩与时间线 | 事件时间轴 | `/api/timeline` |
| 行业数据 / 投资日历 | 数据表 | `/api/industry-data` |

其中 `/api/topic/{id}` 的返回结构最值得借鉴：

```
{ title, tag, date, summary,
  narrative: [{ h, p }, ...],   // 分节叙事："来龙去脉"
  impact,                       // 影响判断
  nodes[], tickers[],           // 相关主体
  newsRefs[], actionLink }      // 相关新闻、行动入口
```

**要点**：AInvest 的专题页之所以"信息量大"，是因为它把一篇报道升级成了一条**有固定章节、有影响判断、有相关主体、有延伸阅读**的叙事线。

## 三、可借鉴清单

### P0 · 立刻可做（本轮已实现）

1. **结构化解读**：把"一句话导读"扩写成七段式解读（对应 AInvest 的 `summary + narrative + impact`）。
2. **固定骨架的详情页**：速览块 → 要点 → 背景 → 意义与影响 → 原文金句 → 启示 → 思考题 → 相关阅读。
3. **原文配图作为头图**：复用站内 `/api/img-proxy` 签名图片代理与既有取图口径。

### P1 · 近期可做（建议下一步）

4. **事件时间轴**：同一 `fact` 下的多条报道按时间排出"来龙去脉"，直接呼应 AInvest 的 `narrative`。
5. **相关主体标签**：从解读中抽取"涉及部门 / 文件 / 群体"，做成可点击标签，串起站内相关条目。
6. **图解卡片**：为高频主题（如"就业""教育强国"）做一张静态 SVG 图解，嵌进解读页。

### P2 · 中期可做

7. **政策日历**：把"发布时间 + 生效时间"整理成日历视图，呼应 AInvest 的投资日历。
8. **看板式首页**：热点榜 + 解读榜 + 来源分布，做成终端式首屏。

### P3 · 可选

9. 数据可视化（政策数量趋势、主题热度曲线）——需要先有稳定的时间维度数据。

> 注意：思政场景与投研场景不同，**不做"资金流向/泡沫监控"类的量化模块**，聚焦"政策理解 + 育人参考"。

## 四、痛点诊断

| 现象 | 根因 | 对策 |
| --- | --- | --- |
| AI 导读字数太少 | 原 prompt 只产出 `background / keyPoints / implications` 三段，信息量天然有限 | 扩写为七段结构化输出，并把送入模型的正文字数上限用到 6000 字 |
| 详情页没有图片 | 解读页从未取过图；原文配图只出现在条目页 | 复用 `articles.media` + `/api/img-proxy`，按"宽 ≥ 480"口径取头图 |
| 页面单调、信息量不足 | 版式是"一段话 + 两个小节"，没有层次 | 固定骨架重排，每屏都有可读内容 |

## 五、P0 改造明细

### 5.1 结构化导读扩写

**Prompt**：`industry/prompts/insight.md`（已重写）
七段输出：`tldr`（一句话速览，≤120字）/ `background` / `keyPoints`（≤6条）/ `significance` / `quote`（原文金句）/ `implications` / `questions`（≤5条）。

> 版本机制：`promptVersion("insight")` 取文件内容 sha256 前 10 位。**改了 md 就等于改了版本号**，因此旧解读会被自动识别为"版本过旧"并重建。

**生成器**：`packages/backend/src/reports/insights.ts`（已改）
- `InsightSchema` 扩到七字段；
- `pendingInsights` 从"事件从未生成过"改为 **"事件没有本版解读"**——LEFT JOIN LATERAL 取该事件已有解读的 version，`version IS DISTINCT FROM 当前版本` 即需重建；
- 写入改为 `INSERT ... ON CONFLICT (article_id) DO UPDATE`，并在重建时清理同事件旧代表条目上的遗留行；
- `maxTokens` 提到 2200。

**契约**：`packages/contracts/src/site.ts`（已改）
- `InsightView` 增加 `tldr`；
- 新增 `InsightCover`、`InsightRelated`；
- `InsightDetail` 增加 `significance / quote / questions / cover / related`。

**迁移**（每个文件一条语句，符合在线迁移安全规则）：
| 文件 | 内容 |
| --- | --- |
| `0061_insights_structured.sql` | `ADD COLUMN tldr text NOT NULL DEFAULT ''` |
| `0062_insights_significance.sql` | `ADD COLUMN significance text NOT NULL DEFAULT ''` |
| `0063_insights_quote.sql` | `ADD COLUMN quote text NOT NULL DEFAULT ''` |
| `0064_insights_questions.sql` | `ADD COLUMN questions jsonb NOT NULL DEFAULT '[]'::jsonb` |
| `0065_insights_version.sql` | `ADD COLUMN version text NOT NULL DEFAULT ''` |

均已通过 `migrationPlan()` 在线安全校验（结果均为 `transaction`）。

### 5.2 详情页骨架重排

**文件**：`apps/web/app/routes/insight-detail.tsx`（已重写）
新骨架：面包屑+评分 → 标题 → **头图** → **速览块** → 要点 → 背景 → 意义与影响 → 原文金句 → 对辅导员意味着什么 → 思考与讨论 → 相关阅读 → 站内阅读/查看原文 + AI 免责声明。

**列表页**：`apps/web/app/routes/insights.tsx`（已小改）卡片摘要优先显示 `tldr`，为空时回退 `background`。

### 5.3 原文配图抽取

在 `insights.ts` 内新增：
- `insightCover(articleId, factId)`：以"本条原文优先、其次同事件其他报道"的顺序，取 `articles.media` 中宽 ≥ 480 的第一张图，经 `proxiedImage` / `proxiedImageSet` 签名输出（与日报头图 `leadCover()` 同一口径）；`body_mode = 'summary'` 的条目不外借图。
- `insightRelated(articleId, factId)`：同事件的其他公开报道，最多 6 条，按评分倒序。

站内图片一律走同一域的 `/api/img-proxy`，无需额外配置图片域名或 CSP。

## 六、部署与验证

### 6.1 部署

```bash
# 1) 本地：提交并推送
git add -A && git commit -m "feat(insights): 结构化政策解读 + 详情页骨架 + 原文配图"
git push site main

# 2) NAS：
cd /volume2/docker/aihot/sizhengzhihui
git pull            # 若该目录未用 git 管理，则把改动文件上传覆盖
docker compose up -d --build
```

> **迁移会自动执行**：compose 的 `setup` 服务运行 `node scripts/migrate.ts`，`api`/`worker` 依赖它成功后再启动，因此 0061–0065 无需手工执行。
> 若改了 `.env`，务必 `docker compose up -d --force-recreate api worker`（仅 `restart` 不生效）。

### 6.2 验证

1. **生成**：解读由 worker 的 `reports.insights` 定时任务（`*/10 * * * *`）分批生成；可在后台任务页观察。老解读会因版本变化被重建，属预期。
2. **接口自检**：
   ```bash
   curl -s http://NAS-IP-REDACTED:3000/api/site/insights | head -c 800
   curl -s "http://NAS-IP-REDACTED:3000/api/site/insights/<articleId>" | head -c 1200
   ```
   应能看到 `tldr`、`cover`、`related` 等新字段。
3. **页面**：`/daily` 列表卡片显示一句话速览；点开详情页可见速览/要点/背景/意义/金句/启示/思考题/相关阅读与配图。

### 6.3 兼容与回退

- **旧解读**：新列有默认值，`tldr` 为空时列表与详情页自动回退显示 `background`，不会出现空白。
- **不需要重建**：若希望保留旧解读原样，可不触发重建（重建只发生在版本不一致时）。
- **回退**：`git revert` 代码即可；新增列可保留不用，无破坏性。

## 八、P1 落地明细（事件时间轴）

**目标**：把解读页从“单篇读”升级为“看事件来龙去脉”——同一 `fact` 下的多篇报道，按时间升序排成时间轴，直接呼应 AInvest 专题页的 `narrative`。

**做法（复用既有能力，无新数据、无迁移）**：

| 层 | 文件 | 改动 |
| --- | --- | --- |
| 契约 | `packages/contracts/src/site.ts` | 新增 `InsightTimelineItem`（`id / title / sourceName / date / current`）；`InsightDetail` 增加 `timeline` |
| 后端 | `packages/backend/src/reports/insights.ts` | 新增 `insightTimeline()`：按 `p.fact_id` 取公开报道，`order by coalesce(published_at, discovered_at) asc`，`limit 20`；`insightDetail()` 并行返回 |
| 前端 | `apps/web/app/routes/insight-detail.tsx` | “背景”之后新增“事件时间轴”小节；当前解读依据的那篇标注“本篇”；“本篇目录”同步 |

**设计要点**：沿用既有 `Section` 语法（15px 标题 + 15.5px 正文、行高 1.9）；时间轴用 1px 竖线 + 圆点，当前项用 accent 圆点 +“本篇”文字徽标（颜色非唯一载体）；时间用 `monthDayTime`（北京时区），与站内口径一致；`timeline.length <= 1` 时不渲染。

**验证**：`npm run typecheck` 通过；**无需数据库迁移**；时间轴为实时查询，**无需重建解读**。

**回退**：删除前端小节即可，`timeline` 为纯新增字段、可保留。

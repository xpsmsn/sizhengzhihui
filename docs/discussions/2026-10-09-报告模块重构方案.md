# 报告模块重构方案（取消日报 + 政策解读）

- 日期：2026-10-09
- 状态：设计稿（待确认后实施）
- 决策（已定）：① 取消日报；② 政策解读触发线 **score ≥ 82**；③ 展示位放在**原日报页**（重设计）；④ 周报出刊**不变**（周一 10:00，北京时间）
- 相关文件：`packages/backend/src/reports/*`、`apps/worker/src/schedules.ts`、`apps/web/app/routes/{daily-archive,report-detail,report-latest}.tsx`、`apps/web/app/components/shell/nav.ts`、`site/site.ts`

---

## 一、为什么要改

现状是**日历驱动**：每天 08:00 硬出一份日报（规则生成），窗口内没有够格条目就出"安静"版；周报/月报只是**把日报汇编**。思政内容不是每日都有"大事"，按天硬出必然经常空。**根因是"日报"这个频次，不是文案。**

改后：**事件驱动（政策解读）+ 周综述**，从源头消除空窗。

---

## 二、现状（关键位置）

| 环节 | 位置 | 说明 |
|------|------|------|
| 调度 | `apps/worker/src/schedules.ts` → `reports.compose`（每半点） | 调 `composeDueReports()` 补齐到期未出的一期 |
| 日报 | `reports/compose.ts` `composeDaily()` | 规则生成，不出模型 |
| 周报/月报 | `reports/compose.ts` `composePeriod()` | **从期间内的日报汇编** + 模型写总述 |
| 周报取数 | `reports/edition.ts` `periodEntries()` | `SELECT ... FROM reports WHERE kind='daily'` —— **强依赖日报** |
| 精选取数 | `reports/edition.ts` `candidates()` / `dailyEdition()` | 直接从精选集 + 事件归并构建 |
| 页面 | `/daily`（`daily-archive` / `report-latest` / `report-detail`） | 日报归档 + 最新 + 详情 |
| 导航 | `nav.ts` `{ to: "/daily", label: 日报 }` | 同时覆盖周报/月报 |

**核心耦合**：周报/月报的条目来自日报；取消日报必须同时改周报取数。

## 三、改动设计

### A. 取消日报

1. **停止出刊**：`composeDueReports()` 不再生成 `daily` 期（只保留 weekly / monthly）。
2. **周报取数改源**：`periodEntries()` 改为**直接从精选集构建**——复用 `candidates(start, end)` + 事件归并（与 `dailyEdition` 同一套），不再读 `reports` 里的日报。
   - 即：把"先驱日报、再汇编日报"改成"直接从精选取数、归并成事件"。
3. **旧日报**：历史 `reports(kind='daily')` **保留不删**，但不再新增；页面不再按"日报"呈现（见 C）。
4. **文案**：`site/site.ts` 里所有"每天…出日报"的说法改为"事件驱动解读 + 每周综述"。

### B. 政策解读模块（新，事件驱动）

**触发**：条目满足 `selected = true AND score ≥ 82` 时，生成一篇解读。

**生成**（LLM，新 prompt `industry/prompts/insight.md`）：
- 输入：该条目的标题 + 摘要 + 正文节选（+ 同事件的其他报道作为背景）
- 输出（结构化 JSON）：`{ background, keyPoints[], implications }`（背景 / 要点 / **对辅导员工作的启示**），总长 150–300 字
- 防幻觉：沿用现有 `grounded()` 校验（不得出现原文没有的数字/机构名）

**存储**：新表 `insights`
```
article_id   text primary key
score        int
title        text
background   text
key_points   jsonb
implications text
model        text
generated_at timestamptz
```
（迁移文件 `database/migrations/<新编号>.sql`）

**触发时机**：发布后新增一个异步步骤（`publish` 完成 → 若 score≥82 入队 `insight`），复用现有 receipts/队列机制，避免发布路径阻塞。

**可选**：生成后推送飞书（走现有 notify 通道，可开关）。

### C. 原日报页重设计（展示位）

把 `/daily` 从"日报归档"改成 **「政策·解读」流**：

- **列表页 `/daily`**：
  - 顶部：最新一篇解读（大卡片：标题 + 解读摘要 + 来源 + 评分角标）
  - 下方：解读卡片列表（时间倒序，每条：标题 + 一句背景 + "要点 N 条"）
  - 侧栏/顶部切换：**周报 / 月报**入口（保留原周报、月报页面，不混进解读流）
- **详情页 `/daily/:articleId`**：单篇解读全文（背景 / 要点列表 / 对辅导员的启示 + 原文链接）
- **空状态**：还没有达标条目时显示"暂无解读，出现 82 分以上的重要讲话或政策文件时会自动生成"（**不出现"安静/无大事"**）

> 备选（更保守）：`/daily` 顶部保留最新周报入口，下面接解读流。若你希望"报告感"更强，用这个。

### D. 周报（保持不变）

- 出刊时间不变（周一 10:00）。
- 仅取数方式随 A-2 改为"直接从精选集"，对读者无感。

## 六、决策与实现状态（2026-10-09）

### 已确认的 5 项
1. **页面形态**：周报入口 + 解读流。
2. **解读不得冲突矛盾**：只依据给定材料，不添加材料没有的事实，不与其他条目矛盾。
3. **结合时政与高校视角、基于原文的再表达**：提示词驱动，对原文做 LLM 解读后**用自己的话输出**，只给解读、原文跳转——规避版权。
4. **不推飞书**。
5. **同事件合并**：同一事件取评分最高的条目，合并成一篇解读。
